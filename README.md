# 二维矩形排样算法与实验

这是一个二维矩形排样的算法课程项目。给定一张固定大小的板材和一组矩形零件，尝试通过不同的排样规则、搜索方法与参数组合，提高装入面积。

项目主要研究两个问题：**怎样把零件放进去，以及怎样通过搜索找到更好的放置优先级。** 使用Java实现算法，在gcut1–12上进行对比、调参与多种子复验。前端用于查看矩形坐标、排样结果和收敛曲线，方便检查和演示算法。

## 问题定义

- 每个零件最多使用一次，可以只装入其中一部分。
- 根据配置允许或禁止旋转90°，不允许任意角度旋转。
- 所有零件必须在板材内，任意两件不能重叠，边界相接允许。
- 目标是最大化装入总面积，利用率为装入面积除以板材面积。

这里研究单张板材的装入问题，不是最少板材数问题，也没有输出加工刀路或切割树。

## 算法思路

### 排列搜索与几何构造

搜索算法维护零件ID的完整排列，表示放置优先级。解码器读取这个排列，按照自己的候选位置、评分和空间更新规则构造二维布局，再把装入面积反馈给搜索算法。

搜索过程主要比较面积。结束后，历史最好排列重新解码成包含坐标与朝向的 `Solution`，再交给独立的 `SolutionValidator` 检查。缓存只复用排列对应的面积，不代替最终布局和合法性验证。

### 搜索方法

| 方法 | 本项目中的主要思路 |
|---|---|
| Tabu-Move | 交换两个零件的优先级，每轮选择最好允许邻居，用近期交换对记忆限制回退，严格超过历史最好时特赦 |
| SA | 随机交换生成候选，面积不降时接受，变差时按面积差与温度计算接受概率，再逐层降温 |
| ACO | 用零件相邻关系的信息素逐位构造排列，依据解码质量强化本轮精英和历史最好路径 |
| ILS | 扰动当前排列，再用首次改进执行交换局部搜索，历史最好单独保存 |
| Adaptive GA | 使用排列交叉和变异，依据父种群质量调整概率，变异概率参考变异前子代 |
| GA+Tabu | 在遗传迭代中按间隔选择个体执行局部Tabu，严格改善且不重复时回写种群 |

### 排样引擎

| 引擎 | 空间表示与放置规则 |
|---|---|
| Shelf BAF Global | 按水平层管理空间，跨剩余零件和可放层比较层尾面积 |
| Shelf Floor-Ceiling | 先放开放层地板，再利用已闭层天花板空隙 |
| Bottom-Left | 从已放矩形边界生成候选坐标，先比较底部，再比较左侧 |
| Continuous Bottom-Left | 枚举顶部入口，交替下降与左移到稳定位置，再择优 |
| Skyline | 用水平段维护轮廓，处理最低有效段，按贴合评分选择零件 |
| Skyline BL-WM | 使用底左轮廓候选，并先尝试废物地图中的可回填空隙 |
| Guillotine | 用不重叠自由矩形记录余区，每次分割选中的区域 |
| MaxRects BEST | 允许自由矩形重叠，分别运行五种评分，按最终装入面积择优 |

默认实验选取这14个代表入口。另外保留选层评分、禁忌属性、GA局部强化等变体，共46个算法配置入口。后续组合实验接通了8个原生解码入口和93个内核适配入口。**配置数不等于独立算法数量，也不能把任意参数组合都视为有效配置。**

具体流程、参数和实现差异见[算法说明](docs/algorithms/README.md)。

## 实验关注什么

1. 固定排样引擎，改变搜索方法，观察优先级优化的效果。
2. 固定搜索方法，改变排样引擎，观察空间表示与放置规则的影响。
3. 改变排序、旋转权限与参数，寻找每个实例的已知最好配置。
4. 固定一套完整配置，在全部实例上用新种子复验，考察平均水平与稳定性。

结果需要同时看最好值、均值、最差值、峰值命中次数和耗时。一次高分说明发现过该布局，不表示随机运行通常都能达到。不同算法的评价计数和缓存计费口径也不同，同样的名义评价预算不保证相同计算成本。

### 最近一轮组合实验

在源码基线 `b718ca3`、登记配置空间和9小时墙钟预算下，完成1,415,601次运行，覆盖41,018套配置。12个实例各选出一套已发现最好配置，其中5个实例刷新历史参考。

跨实例固定配置为 **GA_TABU + 原生MAXRECTS + LONG_SIDE_DESC + 允许旋转**，使用STANDARD参数与20,000次名义评价预算。每实例10个新种子复验后，等权平均利用率为 **96.42%**，按板材面积加权为 **96.30%**。它在6套完成相同协议全实例复验的候选中均值最高，不代表全部配置都完成了同等复验。

这些结果是本轮条件下发现的已知最好结果，没有数学全局最优证明。完整统计口径、逐实例结果及原始文件位置见[组合实验记录](docs/experiments/RESULTS.md)。

## 运行算法与实验

算法与命令行运行需要JDK 17+，不需要先启动前端。仓库带Maven Wrapper。

```bash
# 编译、测试并打包
./mvnw clean verify

# 按配置文件运行，逐实例输出面积、利用率、耗时与验证结果
java -jar target/rectangle-packing-1.0.0.jar --config config/example.properties

# 14个代表入口的多种子实验
./scripts/run-experiments.sh benchmark gcut01 results/benchmark 5 20261012 STANDARD

# 搜索方法与原生解码器的组合对比
./scripts/run-experiments.sh decoder-matrix gcut01 results/decoder-matrix 20000 5 20261012 STANDARD
```

[示例配置](config/example.properties)可以指定算法、解码器、初始排序、旋转、种子和预算。`QUICK`适合检查流程，`STANDARD`使用常规实验参数；它们都不等于本轮调参后的每实例最好配置。

普通批量实验会生成：

| 文件 | 统计层级 |
|---|---|
| `runs.csv` | 一次独立运行，包含种子、面积、利用率、耗时和合法性 |
| `summary.csv` | 算法与实例的组合，汇总多次运行 |
| `overall.csv` | 跨实例汇总，解释时仍需核对具体列的计算方式 |
| `traces.csv` | 搜索过程的历史最好面积，不是当前解面积 |
| `layouts/`、`convergence/` | 排样与收敛曲线SVG |

更多参数扫描、单家族对照、时间预算和Windows命令见[实验运行指南](docs/experiments/RUNNING.md)。本地完整实验产物位于被Git忽略的 `results/` 中，不随源码克隆获得。

## 可视化辅助

需要交互查看布局和实验记录时，可以启动本地界面：

```bash
./mvnw -Pfrontend package
java -jar target/rectangle-packing-1.0.0-web.jar
```

打开 `http://localhost:8080/`。界面调用同一份后端算法，便于查看零件位置、比较结果和观察轨迹。算法本身不依赖浏览器运行。前端开发、API和记录管理的细节见[运行与可视化说明](docs/visualization/RUNNING.md)。

完整阅读顺序与文件归属见[文档索引](docs/README.md)。
