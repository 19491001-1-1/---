# 测试策略

项目测试分为五层，避免只验证某一组基准结果。

1. **几何单元测试**：验证评分、切割、自由矩形维护、排序和搜索算子。
2. **算法回归测试**：固定实例与随机种子，检查各算法的已知行为和统计量。
3. **全入口边界测试**：46 个入口统一运行空实例、单件、全部超限和混合实例。
4. **随机不变量测试**：固定种子生成随机板材与零件，交替启用旋转，独立验证边界、不重叠、身份一致和唯一使用。
5. **质量基线测试**：搜索优化层和排样引擎层共 14 个工程主入口，在 `gcut3` 上必须达到保守的最低装入面积，防止重构后仍然合法但效果明显退化。

原生 JUnit 另外覆盖配置文件解析、未知键拒绝、预算互斥、checkpoint 往返恢复、六种搜索主入口与八种解码器的交叉组合，并单独确认每个解码器都不会吞掉搜索器给出的优先级顺序。`RegressionSuiteTest` 仅负责将尚未迁移的断言式测试纳入 JUnit 生命周期。

质量阈值故意低于当前结果，只用于识别明显回退。算法得到改进时无需修改阈值；只有问题定义、默认参数或解码规则发生经过论证的变化时，才应重新测量并调整基线。

完整验证命令：

```bash
./mvnw clean verify
```

覆盖率报告位于 `target/site/jacoco/index.html`。覆盖率用于发现测试盲区，不作为算法正确性的单独证明。

构建质量门禁要求行覆盖率不少于 80%、分支覆盖率不少于 70%。批量实验若发现任意非法解，会先写出诊断报告，再以失败状态终止，避免错误结果进入后续统计流程。
