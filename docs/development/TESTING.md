# 测试与质量保障

项目测试分为九层，避免只验证某一组基准结果。

家族目录另验证全部稳定配置无重复无遗漏、五个兼容配置不被标为默认代表。Skyline WM 对照测试覆盖两种取件模式与两种评分的配对导出。冠军回归验证解码器身份、并列结果与非法结果排除；Playwright 的 `algorithm-families.spec.ts` 验证兼容开关、家族筛选、搜索空状态与移动端横向溢出。

1. **几何单元测试**：验证评分、切割、自由矩形维护、排序和搜索算子。
2. **算法回归测试**：固定实例与随机种子，检查各算法的已知行为和统计量。
3. **全入口边界测试**：46 个入口统一运行空实例、单件、全部超限和混合实例。
4. **随机不变量测试**：固定种子生成随机板材与零件，交替启用旋转，独立验证边界、不重叠、身份一致和唯一使用。
5. **质量基线测试**：搜索优化层和排样引擎层共 14 个工程主入口，在 `gcut3` 上必须达到保守的最低装入面积，防止重构后仍然合法但效果明显退化。
6. **Web API 测试**：使用 Spring Boot + MockMvc 验证元数据、代表算法映射、实例白名单、六种搜索器求解、预算互斥、未知枚举和统一错误响应。
7. **实验生命周期测试**：验证后台任务矩阵的取消、重试、删除与终态语义，以及 SSE 事件的序号、补发与终止保证。
8. **持久化与跨进程恢复测试**：验证写入格式的往返对称性，以及「进程重启后任务、进度、明细与事件序号」的恢复语义。
9. **产物与存储保留测试**：验证 CSV/HTML/SVG 产物从真实求解链路生成、下载端点的越界拒绝，以及存储目录的容量回收只碰终态任务。

第 7 层的两个测试类都建立在可注入的时间控制之上，而不是靠真实算法的耗时碰运气。
`ExperimentTaskService` 的求解入口抽象成包级私有的 `CellSolver` 接口，生产环境注入真的
`SolveService`，测试注入一个可以按格子指定延迟的实现。这样做的直接原因是曾实测过：QUICK
档位下所有代表算法都在 ≤47ms 内收工（算法内部的迭代上限远早于评价预算生效），
想靠真实组合造出「一个跑得很慢的格子」根本造不出来，进度滞后和取消灵敏度的断言也就无从写起。

- `ExperimentLifecycleTest`：取消后只保留有效部分结果、重试只补缺结果的格子、
  运行中重试被拒、终态取消被拒、无缺口重试被拒、未知任务报 404、
  运行中删除被拒、终态删除同时清理内存索引与持久化目录、
  最慢格子还在跑时进度照常前进（这条直接盯住「按提交顺序等待」的旧缺陷）、
  取消靠中断而不是等格子自然结束。
- `ExperimentEventLogTest`：序号从 1 单调递增、首次订阅不补发、`replayAfter` 的过滤边界、
  已收到最新事件时不补发、超容量时丢最旧但保留序号、终态事件判定。
- `WebApiIntegrationTest`：取消与重试端点在终态下的 409 错误码、SSE 流的 `event:` 名与
  `id:` 序号、带 `Last-Event-ID` 的重连收尾。

第 8 层用 `@TempDir` 给每个用例一个独立临时目录，绝不写进仓库。「跨进程」的做法是：
用同一个临时目录先后建两个服务实例，第一个跑到一半直接 `close()`（等价于进程被杀，
不做任何优雅收尾），第二个在构造时从该目录恢复。

- `ExperimentTaskStoreTest`：元数据全字段往返、可空预算字段不使字节流错位、
  时间戳保留亚毫秒精度、单格结果按下标各归各位且乱序写入不影响、
  任务标识不能逃出存储根目录、残留临时文件不被计入、损坏任务被跳过而非启动失败、
  重复保存就地覆盖、同一任务的并发元数据写入不互相踩。这一层的价值不在覆盖率，
  而在于把两条约定钉死：一是「写入端与读取端必须逐字段对称」——位置式二进制格式里
  任何一处条件读写不一致，症状都是「任务莫名其妙不见了」，极难从上层排查；
  二是「同一任务的并发写入各有各的暂存文件」——共用固定名字时后写者会截断前写者，
  症状是一条无法复现的 `NoSuchFileException`，乃至状态被静默回退。
- `ExperimentRecoveryTest`：重启时在跑的实验转为已取消且保留已算完的格子、
  恢复后重试只执行缺口部分（用计数求解器证明没有重算）、排队中的实验自动重新排队、
  等待重启时机一律盯磁盘而不是内存（结果数组由工作线程先写，文件由提交线程后写，
  盯完成数会撞上两者之间的窗口，测试自己变成随机的）、
  终态任务原样恢复、列表按创建时间倒序、取消标记跨重启保留、
  坏任务目录与坏格子文件各自降级、事件序号跨重启继续递增、
  订阅恢复后的终态任务能立刻拿到终止事件。
- 杀进程时机：暂存文件残留、只有 `meta.bin` 没有格子、写到一半的格子文件，
  三种残骸都只影响自己那一格，不影响任务可读与可恢复。
- 只读存储目录：以 `posix` 权限位把目录降为只读（非 root 时生效，root 下自动跳过），
  验证落盘失败不会让整个实验失败——结果仍在内存中可用，重试也不会把事情搅得更糟。

第 9 层把「产物」当作一条完整链路来测，而不是只测格式化函数：

- `ExperimentArtifactServiceTest`：终态才允许生成、生成前清单为空而不是 404、
  清单包含 `report.html` / `runs.csv` / `experiment-metadata.properties`、
  嵌套名字（`convergence/gcut1.svg`）可下载、越界名字与不存在的名字报同一个 404、
  生成失败时旧产物不被破坏。
- `ExperimentStoreRetentionTest`：超限只删最旧的终态任务、排队中与运行中的任务永不删
  （哪怕它们最旧）、上限以内的目录一个都不动、非正数上限关闭保留策略、
  删除是递归的且容忍目录不存在。
- `WebApiIntegrationTest` 的两个产物用例走**真实求解链路**，验证适配器确实能把一份实验
  转成可生成的产物；下载断言覆盖「附件下发」「内容非空」与「任务目录里的
  `meta.bin` / `cells/*.bin` / `*.layout.bin` 一律不可下载」。

跨重启的产物与记录同样有前端一层：`ExperimentArtifacts.vue` 在记录页嵌入，
因此产物面板必须能在没有内存任务状态的情况下独立工作。

**前端第 1 层（组件与逻辑单测，Vitest + jsdom）**：`api/client.ts` 的错误映射、
blob 下载与文件名解析；`stores/catalog.ts` 的加载、去重与失败重试语义；
`useSolveForm` 的预算互斥与上下界校验；`ExperimentArtifacts.vue` 的清单加载、
按段编码的下载 URL 与对象 URL 回收；`ConvergenceChart.vue` 把 echarts 换成替身，
只断言传给 `setOption` 的阶梯数据。

分析相关的三块各有分工：`analysis/experimentAnalysis.ts` 是纯函数层，钉死分位数插值、
「非法结果不进均值但计总数」、与核心报告一致的排名口径（并列同名次、之后跳号）、
箱线图的 IQR 离群判定、热力图缺组合留空而不补 0、以及收敛系列「取轨迹最长的一次」；
`HeatmapChart` / `BoxplotChart` / `ConvergenceCompareChart` 三个组件的测试盯的是
容易骗人的地方——缺数据渲染成破折号而非 0%、箱线图归一用所有系列的并集而不是各自归一
（后者会让宽窄不同的两行看起来一样宽）、收敛曲线用阶梯且颜色按算法名固定；
`AnalysisView` / `RecordsView` 两个视图的测试守的是粘合逻辑：只为选中任务取数、
四张图共用同一份结果、筛选与排序、同值排序靠 id 兜底不抖动、以及轮询在有任务结束时自停。

**前端第 2 层（端到端冒烟，Playwright）**：`e2e/experiment-smoke.spec.ts` 起真实前后端，
验证实验完成、产物生成、刷新后按路由恢复当前任务，以及 390px 视口下七个导航入口完整可用；
点选一个 2×2 矩阵、预览、启动，等进度到 100% 与产物清单出现。它守的是单测天然绕过的东西：
SSE 建连与收尾、前后端字段名一致性、真实浏览器的下载与渲染。
`e2e/analysis-smoke.spec.ts` 再跑一个小实验进「结果分析」页，断言热力图 4 格都有数、
排名给出百分比、箱线图两行且收敛曲线渲染出 SVG——「后端返回的口径与图表要的对不对得上」
只有真数据能验，单测里的 JSON 是手写的，字段对了不代表口径对了。
`e2e/adaptive-child-fitness.spec.ts` 检查自适应 GA 的子代评分规则在求解页和算法目录中一致呈现，
再通过真实求解与实验产物验证评价预算、合法性和版本元数据。

前端对应一层：`useExperimentEvents` 把 SSE 建连抽象成可注入的工厂，测试用 `FakeEventSource`
替身（而非 jsdom 缺失的真实 `EventSource`），覆盖事件驱动更新、首次订阅不带序号、
终止事件关闭连接、断线重连带上次序号、达到重连上限后放弃、终态不再重连、`dispose` 停止重连。

**单 jar 部署的 SPA 回退**：`SpaFallbackTest` 用测试资源里的 `static/index.html` 夹具
（默认构建不打包前端，因此夹具只存在于测试 classpath）验证四件事：前端深链与嵌套路由回退到
`index.html`、根路径由 Boot 的欢迎页转发到 `index.html`、未知 `/api` 路径**不被回退吞掉**
并返回结构化 404、带扩展名的缺失静态资源返回 404 而不吐 HTML。后两条是这个回退最容易出错、
且一旦出错就掩盖真实错误的地方。

CI 对部署形态另有一层守护：`.github/workflows/ci.yml` 的 `web-jar` job 执行
`./mvnw -Pfrontend -DskipTests package` 并断言 web jar 内确实含 `static/index.html` 与
`static/assets/`。**这是单 jar 路径唯一能长期守住的地方**——本地构建过一次不代表下次仍能打出来。

完整验证命令：

```bash
./mvnw clean verify            # 后端：测试 + JaCoCo 门禁
cd frontend
pnpm install
pnpm check                    # 前端：类型检查 + 单测 + 覆盖率门禁
pnpm build                    # 前端：生产构建
```

覆盖率报告位于 `target/site/jacoco/index.html`（后端）与 `frontend/coverage/index.html`（前端）。
覆盖率用于发现测试盲区，不作为算法正确性的单独证明。

构建质量门禁要求后端行覆盖率不少于 80%、分支覆盖率不少于 70%；前端语句与行覆盖率
不少于 72%、分支不少于 72%、函数不少于 64%（`frontend/vite.config.ts`）。批量实验若发现
任意非法解，会先写出诊断报告，再以失败状态终止，避免错误结果进入后续统计流程。

端到端冒烟需要真实的前后端，因此不进 `pnpm check`，单独跑：

```bash
# 终端 1：后端（任意端口，前端默认代理到 8080）
java -jar target/rectangle-packing-1.0.0-web.jar

# 终端 2：前端与浏览器
cd frontend
pnpm e2e:install     # 首次需要：下载 Chromium（可用 PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 跳过）
pnpm test:e2e        # 等价于 playwright test
```

后端没起时冒烟用例会直接失败，而不是静默跳过——被跳过的接缝等于没人守。
`E2E_BASE_URL` 指到已有环境时，Playwright 不再自己拉起前端。
