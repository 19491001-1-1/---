# 组合排样与调参实验

本轮实验在gcut1–12上组合搜索器、排样内核、排序、旋转与参数。实验有两个目标：每个实例分别寻找高面积配置，以及寻找一套跨实例表现较好的固定配置。两条结果线分开报告。

## 实验条件

- 算法源码基线：`b718ca36eafe3a36fb41bf233bfaeadf4b96e44e`。
- 授权墙钟上限为9小时，采用4个独立JVM worker。墙钟包含调度与收尾，不等于9小时纯搜索。
- 覆盖41,018个不同configurationId，完成1,415,601次运行，记录中非法0、失败0。
- 采用筛选、预算阶梯、定向加深和独立复验。不同阶段复用配置，阶段配置数不能直接相加。
- 仍有1,016,262项任务未完成并保留登记，没有穷尽配置空间。

搜索入口和内核适配入口分别计数。构造式SOLVER使用自身内核，记录中的decoder标签不一定参与实际放置。以下对gcut1和gcut9直接标为“自身内核”，避免误写成与Skyline组合。

## 跨实例固定配置

固定配置 `354de8e136c63985`：GA_TABU、原生MAXRECTS、LONG_SIDE_DESC、允许旋转、STANDARD参数、20,000次名义评价预算。参数覆盖为空，继承基线中的默认值。

每实例使用相同的10个新种子。先对该实例的装入面积取均值，再除以对应板材面积，得到实例平均利用率。12个实例等权平均为 **96.4211%**；各实例平均面积之和除以板材面积之和为 **96.3006%**。最低实例均值为gcut1的 **93.0176%**。

这套配置在6套完成同协议全实例复验的候选中均值最高。该结论不能扩展为“41,018套配置都经过相同复验后排名第一”，也不能把12个单实例峰值拼成该配置的成绩。

## 结果怎样解释

- 各搜索家族的evaluations口径不同。Tabu与SA缓存命中仍计候选评价，ACO、GA、ILS主要按未命中解码计数。名义预算相同不保证真实工作量相同。
- 迭代或停滞条件可能先终止搜索，ACO尤其需要核对实际消耗，而不是只看请求预算。
- 严格面积上界来自面积子集和约束，不代表存在对应的二维布局。合法解达到该上界可证明装入面积最优，未达到不能反向证明它一定非最优。
- 结果通过独立几何验证后可以比较利用率。要解释某种算法机制的贡献，仍需控制内核、预算、种子和其他参数。
